# 운영 매뉴얼 — 데모데이 현장

대상: 부스에 서 있는 **운영자**. 코드를 열지 않고 손으로 수습할 수 있는 것만 적는다.
설계 근거는 [`ARCHITECTURE.md` §9 폴백 매트릭스](ARCHITECTURE.md).

---

## 1. 운영자 단축키 (무대 모드 전용)

키오스크 화면(`/`, `?debug=1` 없이)에 포커스가 있을 때 동작한다. **화면에는 목록이 뜨지 않는다** —
관객이 보는 것은 무대뿐이다. 유일한 예외는 카메라 실패 화면(ERROR_RECOVER)의 `Shift+D` 한 줄이다.

| 키 | 하는 일 | 언제 쓰나 |
| --- | --- | --- |
| `Shift+D` | 목 카메라 **데모 모드** 토글 | 웹캠이 안 잡힐 때. 켜면 여정을 CREATE 부터 다시 민다 |
| `Shift+R` | **강제 RESET** — 세션 파기 | 관객이 화면을 두고 떠났을 때, 오작동 수습 |
| `Shift+F` | **전체 장애 폴백 화면** 토글 | 앱·GPU·네트워크가 통째로 죽었을 때 |

구현 근거: `src/app/ops.ts` (`OPERATOR_SHORTCUTS`). 이 표와 그 상수가 어긋나면 문서 버그다.

### 왜 `Shift` 조합인가

- 키오스크는 관객이 이름을 입력하는 화면(OWN)에서 `#patternNameInput` 에 자동 포커스한다.
  대문자를 치면 `Shift` 가 눌리므로, **입력 중에는 `Shift+D`·`Shift+F` 를 잠근다.**
  `Shift+R` 만 예외다 — 수습 키가 정작 필요한 순간이 이름 입력 화면이기 때문이다.
- 키는 `event.code` 로 읽는다. 한글 IME 가 켜져 있으면 `event.key` 는 `ㅇ`·`ㄱ` 이 되어
  단축키가 통째로 죽는다. `code` 는 자판 배열을 타지 않는다.
- `?debug=1` 계기판에서는 단축키를 걸지 않는다(개발자는 버튼으로 움직인다).

> **현장 규칙 — 이름 입력 화면에서는 `Shift+R` 부터.**
> 관객이 이름을 짓는 OWN 화면에서는 `Shift+D`·`Shift+F` 가 잠겨 있다(위의 이유).
> 그 화면에서 데모 모드나 폴백 화면이 필요하면 **`Shift+R` 을 먼저 눌러** 세션을 파기하고
> 처음 화면으로 돌아온 다음 누른다. `Shift+R` 은 어떤 화면에서도 항상 먹는다.

### 데모 모드가 하는 일 (`Shift+D`)

`navigator.mediaDevices.getUserMedia` 를 움직이는 캔버스 스트림으로 바꿔치기한다
(`src/vision/mock-camera.ts`). 세그멘테이션·씨앗 추출·패턴 생성·녹화는 **평소와 똑같이** 돈다.

- 켜면 무대 위쪽에 `데모 모드 · 목 카메라` 표기가 뜬다. 관객을 속이지 않는다.
- ERROR_RECOVER(카메라 실패) 또는 ATTRACT 에서 누르면 여정을 CREATE 부터 다시 민다.
  ERROR_RECOVER 는 5초 뒤 ATTRACT 로 넘어가므로, 5초를 놓쳐도 그냥 다시 누르면 된다.
- 체험이 진행 중(CREATE~OWN)이면 화면은 건드리지 않고 **다음 세션부터** 목 카메라를 쓴다.
- 한 번 더 누르면 진짜 카메라가 돌아온다(페인트 루프와 캔버스 스트림도 같이 정지한다).

### 강제 RESET 이 하는 일 (`Shift+R`)

어떤 상태에서든 `RESET` 을 **통과해서** 세션을 파기한다(2초 뒤 ATTRACT).
ATTRACT 로 바로 뛰지 않는 이유는 RESET 진입이 세션 에포크를 올리기 때문이다 —
건너뛰면 늦게 도착한 업로드 응답이 **앞 관객의 QR 을 다음 사람 화면에** 그릴 수 있다.

## 2. 전체 장애 폴백 영상 준비 (`Shift+F`)

`Shift+F` 는 무대 전체를 `public/assets/fallback.mp4` 로 덮는다(음소거·무한 반복).
파일이 없으면 **`폴백 영상 준비 필요` 플레이스홀더**가 대신 뜬다 — 화면이 검게 죽지는 않는다.

> `.gitignore` 가 `*.mp4` 를 막고 있어 이 파일은 **리포에 커밋되지 않는다.**
> 각 현장 머신에서 데모데이 전에 직접 놓아야 한다.

### 준비 방법

1. 정상 동작하는 키오스크로 한 세션을 끝까지 돌리고 화면을 녹화한다.
   - macOS: `Shift+Cmd+5` → 화면 기록. 또는 `npm run preview` 후 OBS 로 창 캡처.
   - 길이 30~60초, 무한 반복해도 어색하지 않게 시작·끝 프레임을 비슷하게 잡는다.
2. 무대 비율(**세로 1080×1920**)로 맞춘다. 다른 비율이면 `object-fit: cover` 로 잘린다.
3. h264 + AAC 없는 무음 mp4 로 인코딩한다 (자동재생은 음소거가 조건이다):
   ```bash
   ffmpeg -i 원본.mov -an -vf "scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920" \
     -c:v libx264 -profile:v high -pix_fmt yuv420p -crf 23 -movflags +faststart \
     public/assets/fallback.mp4
   ```
4. `public/assets/fallback.mp4` 에 놓는다. `npm run build` 로 다시 묶으면 `dist/assets/` 로 복사된다.
   (dev 서버는 `public/` 을 그대로 서빙하므로 빌드 없이도 즉시 확인된다.)
5. 확인: 키오스크를 열고 `Shift+F` → 영상이 재생되면 성공. 플레이스홀더가 남으면 경로·코덱을 다시 본다.

`Shift+F` 도 이름 입력 중에는 잠긴다 — `Shift+R` 로 빠져나온 뒤 누른다(위 현장 규칙).
`Shift+F` 는 켜는 순간 **먼저 세션을 파기한다** — 장애 화면 뒤에서 카메라가 계속 도는 것은
설계 원칙 4(원본 프레임을 남기지 않는다)에 어긋나기 때문이다. 한 번 더 누르면 무대로 돌아온다.

## 3. 폴백 리허설 (카메라 없이 §9 재현하기)

개발 서버(`npm run dev`)에서만 되는 계기다. 프로덕션 번들에는 포함되지 않는다.

| 주소 | 재현하는 것 |
| --- | --- |
| `?failCamera=1` | `getUserMedia` 가 항상 거절 → CREATE → **ERROR_RECOVER** ('카메라 실패' 행) |
| `?mockCamera=1` | 카메라 없이 여정 완주 (무인 검증) |
| `?mockTicket=url` / `=code` | 결과 카드(QR / 오프라인 코드) 렌더만 확인 |
| `?debug=1` | 계기판 — 타임아웃·자동 진행 없이 버튼으로 진행 |

**카메라 실패 → 데모 모드 리허설:**
`http://localhost:5190/?failCamera=1` → 터치 → 동의 → 카메라 실패 → ERROR_RECOVER 안내에
`운영자 · Shift+D — 데모 모드로 계속` 이 뜬다 → `Shift+D` → 목 카메라로 여정이 이어진다.
